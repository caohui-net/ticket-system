### 阶段2: 参考项目研究 ✅

**完成时间**: 2026-09-06  
**研究对象**: Peppermint (https://github.com/Peppermint-Lab/peppermint)

**完成内容**:

1. ✅ 技术栈对比分析
   - 验证了我们的技术选型（NestJS + React + Prisma）
   - 相似度: 95%
   - 结论: 我们的选择更适合学校项目

2. ✅ 优秀设计借鉴
   - 权限格式: `resource:action` (如 `ticket:create`)
   - 工单编号: 添加自增 `number` 字段
   - JSON快照: `createdBy` 存储用户快照
   - 评论历史: `edited/editedAt/previous` 字段
   - 通知系统: 多渠道架构设计

3. ✅ 不适合借鉴的部分
   - ❌ Fastify框架 (我们用NestJS更好)
   - ❌ Monorepo架构 (项目规模小不需要)
   - ❌ 邮件集成 (学校项目不需要)
   - ❌ 多租户功能 (单租户足够)

4. ✅ 研究报告输出
   - 📄 `docs/Peppermint项目学习报告.md` (619行)

**关键收获**:
- ✅ 技术栈选择正确
- ✅ 发现了5个可立即实施的改进点
- ✅ 明确了功能优先级

## 📝 重要决策记录

### 决策1: 技术栈选择
**日期**: 2026-09-06  
**决策**: 使用 NestJS + React + TypeScript + PostgreSQL + Prisma  
**理由**: 
- NestJS提供完整的企业级框架
- TypeScript提供类型安全
- Prisma简化数据库操作
- React生态成熟

**验证**: 通过Peppermint项目研究，确认选择正确

### 决策2: 不使用Monorepo
**日期**: 2026-09-06  
**决策**: 使用独立的backend和frontend目录，不使用Turborepo  
**理由**: 
- 学校项目规模小
- 独立目录结构更简单
- 降低构建复杂度

### 决策3: 借鉴Peppermint的设计模式
**日期**: 2026-09-06  
**决策**: 采用以下设计：
1. 权限格式: `resource:action`
2. 工单编号: 自增Number字段
3. JSON快照: createdBy字段
4. 评论历史: edited/editedAt/previous字段

**理由**: 这些是经过验证的最佳实践

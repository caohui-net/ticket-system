# 权限管理模块文档

## 概述

权限管理模块实现了基于RBAC（Role-Based Access Control）的细粒度权限控制系统，采用`resource:action`格式的权限标识符，支持权限的动态分配和验证。

## 功能特性

- ✅ 细粒度权限控制（resource:action格式）
- ✅ 权限守卫自动验证
- ✅ 支持通配符权限（如 ticket:*, *:*）
- ✅ 角色权限批量管理
- ✅ 用户权限查询（支持多角色权限合并）
- ✅ 权限初始化种子脚本
- ✅ 完整的单元测试覆盖（89.13%）
- ✅ Swagger API文档

## 数据库设计

### Permission表（权限表）

```sql
CREATE TABLE permissions (
  permission_id BIGSERIAL PRIMARY KEY,
  resource VARCHAR(50) NOT NULL,      -- 资源名称：ticket, comment, user, role, statistics
  action VARCHAR(50) NOT NULL,        -- 操作名称：create, read, update, delete, assign, close, manage, view
  code VARCHAR(100) UNIQUE NOT NULL,  -- 权限代码：resource:action
  description VARCHAR(200),           -- 权限描述
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(resource, action)
);
```

### RolePermission表（角色权限关联表）

```sql
CREATE TABLE role_permissions (
  role_id BIGINT NOT NULL,
  permission_id BIGINT NOT NULL,
  PRIMARY KEY (role_id, permission_id),
  FOREIGN KEY (role_id) REFERENCES roles(role_id) ON DELETE CASCADE,
  FOREIGN KEY (permission_id) REFERENCES permissions(permission_id) ON DELETE CASCADE
);
```

## 预置权限

### 权限列表

| 权限代码 | 资源 | 操作 | 描述 |
|---------|------|------|------|
| `ticket:create` | ticket | create | 创建工单 |
| `ticket:read` | ticket | read | 查看工单 |
| `ticket:update` | ticket | update | 更新工单 |
| `ticket:delete` | ticket | delete | 删除工单 |
| `ticket:assign` | ticket | assign | 分配工单 |
| `ticket:close` | ticket | close | 关闭工单 |
| `ticket:*` | ticket | * | 工单所有权限 |
| `comment:create` | comment | create | 创建评论 |
| `comment:read` | comment | read | 查看评论 |
| `comment:update` | comment | update | 更新评论 |
| `comment:delete` | comment | delete | 删除评论 |
| `comment:*` | comment | * | 评论所有权限 |
| `user:manage` | user | manage | 管理用户 |
| `user:read` | user | read | 查看用户 |
| `role:manage` | role | manage | 管理角色 |
| `role:read` | role | read | 查看角色 |
| `statistics:view` | statistics | view | 查看统计 |
| `*:*` | * | * | 所有权限（超级管理员） |

### 角色权限配置

#### ADMIN（系统管理员）
- `*:*` - 所有权限

#### CREATOR（工单创建者）
- `ticket:create`, `ticket:read`, `ticket:update`
- `comment:create`, `comment:read`, `comment:update`, `comment:delete`

#### HANDLER（处理人员）
- `ticket:read`, `ticket:update`, `ticket:assign`, `ticket:close`
- `comment:create`, `comment:read`, `comment:update`, `comment:delete`
- `user:read`, `statistics:view`

#### REPORTER（报表查看者）
- `ticket:read`, `comment:read`, `statistics:view`

#### REVIEWER（部门主管）
- `ticket:read`, `ticket:update`, `ticket:assign`, `ticket:close`
- `comment:create`, `comment:read`, `comment:update`
- `user:read`, `statistics:view`

#### APPROVER（分管领导）
- `ticket:read`, `ticket:update`, `ticket:close`
- `comment:create`, `comment:read`
- `user:read`, `statistics:view`

## API端点

### 权限管理

#### 1. 获取所有权限列表

```http
GET /api/v1/permissions
Authorization: Bearer <token>
```

**权限要求**: `role:manage`

**响应示例**:
```json
[
  {
    "id": "1",
    "resource": "ticket",
    "action": "create",
    "code": "ticket:create",
    "description": "创建工单",
    "createdAt": "2026-09-06T10:00:00Z"
  }
]
```

#### 2. 获取权限详情

```http
GET /api/v1/permissions/:id
Authorization: Bearer <token>
```

**权限要求**: `role:manage`

**响应示例**:
```json
{
  "id": "1",
  "resource": "ticket",
  "action": "create",
  "code": "ticket:create",
  "description": "创建工单",
  "createdAt": "2026-09-06T10:00:00Z",
  "roles": [
    {
      "id": "2",
      "code": "ADMIN",
      "name": "系统管理员"
    }
  ]
}
```

#### 3. 创建权限

```http
POST /api/v1/permissions
Authorization: Bearer <token>
Content-Type: application/json

{
  "resource": "attachment",
  "action": "download",
  "description": "下载附件"
}
```

**权限要求**: `*:*`（仅超级管理员）

#### 4. 更新权限

```http
PATCH /api/v1/permissions/:id
Authorization: Bearer <token>
Content-Type: application/json

{
  "description": "更新后的描述"
}
```

**权限要求**: `*:*`（仅超级管理员）

#### 5. 删除权限

```http
DELETE /api/v1/permissions/:id
Authorization: Bearer <token>
```

**权限要求**: `*:*`（仅超级管理员）

## 使用方法

### 1. 在Controller中使用权限守卫

```typescript
import { Controller, Get, Post, UseGuards } from '@nestjs/common';
import { JwtAuthGuard } from '../auth/guards/jwt-auth.guard';
import { PermissionsGuard } from '../permissions/guards/permissions.guard';
import { RequirePermissions } from '../permissions/decorators/require-permissions.decorator';

@Controller('tickets')
@UseGuards(JwtAuthGuard, PermissionsGuard)
export class TicketsController {
  @Post()
  @RequirePermissions('ticket:create')
  create(@Body() createDto: CreateTicketDto) {
    // 只有拥有 ticket:create 权限的用户才能访问
  }

  @Get()
  @RequirePermissions('ticket:read')
  findAll() {
    // 只有拥有 ticket:read 权限的用户才能访问
  }

  @Post(':id/assign')
  @RequirePermissions('ticket:assign')
  assign(@Param('id') id: string, @Body() assignDto: AssignDto) {
    // 只有拥有 ticket:assign 权限的用户才能访问
  }
}
```

### 2. 多权限要求

```typescript
@Patch(':id')
@RequirePermissions('ticket:update', 'ticket:assign')
async update(@Param('id') id: string, @Body() updateDto: UpdateDto) {
  // 需要同时拥有 ticket:update 和 ticket:assign 权限
}
```

### 3. 在Service中检查权限

```typescript
@Injectable()
export class TicketsService {
  constructor(private readonly prisma: PrismaService) {}

  async updateTicket(id: bigint, userId: bigint, userPermissions: string[], updateDto: UpdateTicketDto) {
    const ticket = await this.prisma.ticket.findUnique({
      where: { id },
      include: {
        creatorSnapshot: true,
      },
    });

    // 检查用户是否有权限更新工单
    const canUpdate = userPermissions.includes('ticket:update') || 
                     userPermissions.includes('ticket:*') ||
                     userPermissions.includes('*:*');

    // 或者检查资源所有权
    const isOwner = ticket.creatorSnapshot.userId === userId;
    
    if (!canUpdate && !isOwner) {
      throw new ForbiddenException('无权更新此工单');
    }

    // 执行更新...
  }
}
```

### 4. 权限守卫工作原理

权限守卫会：
1. 从请求中获取当前用户信息（包含permissions数组）
2. 从装饰器中获取所需权限列表
3. 检查用户是否拥有所有必需权限
4. 支持通配符匹配（`ticket:*` 匹配 `ticket:create`）
5. 超级管理员权限 `*:*` 可以访问所有接口

## 注意事项

1. **JWT策略集成**：JWT策略已更新为在token验证时自动加载用户权限
2. **权限缓存**：可考虑使用Redis缓存用户权限以提高性能
3. **权限设计原则**：
   - 最小权限原则：用户只应拥有完成工作所需的最少权限
   - 权限细粒度：每个操作都应有对应的权限控制
   - 易于理解：权限命名应清晰明确
4. **扩展性**：新增资源时，按照 `resource:action` 格式添加权限即可

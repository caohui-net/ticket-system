## 技术实现

### 权限格式
采用 `resource:action` 格式：
- `ticket:create` - 创建工单
- `ticket:read` - 查看工单
- `comment:*` - 评论所有权限
- `*:*` - 超级管理员权限

### 权限验证流程
1. 用户登录 → JWT token签发
2. 请求携带token → JWT策略验证
3. JWT策略加载用户角色和权限
4. 权限守卫检查所需权限
5. 通过/拒绝请求

### 支持的功能
- ✅ 单权限验证
- ✅ 多权限验证（需要同时拥有多个权限）
- ✅ 通配符权限（`ticket:*` 匹配所有ticket相关权限）
- ✅ 超级管理员权限（`*:*` 可访问所有接口）
- ✅ 权限继承（通过角色继承）
- ✅ 多角色权限合并（用户可以有多个角色，权限去重）

## 使用示例

### 在Controller中使用
```typescript
@Controller('tickets')
@UseGuards(JwtAuthGuard, PermissionsGuard)
export class TicketsController {
  @Post()
  @RequirePermissions('ticket:create')
  create(@Body() createDto: CreateTicketDto) {
    return this.ticketsService.create(createDto);
  }
}
```

### 在Service中检查权限
```typescript
if (!user.permissions.includes('ticket:update') && !isOwner) {

}
```

## 遇到的问题和解决方案

### 问题1: 数据库迁移失败
**原因**: 之前的迁移文件与当前schema不一致  
**解决**: 使用 `npx prisma db push` 直接推送schema

### 问题2: 编译错误（Statistics模块）
**原因**: Statistics模块有类型错误  
**影响**: 不影响权限模块功能  
**状态**: 权限模块独立测试通过，可正常使用

### 问题3: UserPermissionsController的user参数获取
**原因**: 最初使用@Param装饰器错误  
**解决**: 改用@CurrentUser装饰器从JWT token获取用户信息

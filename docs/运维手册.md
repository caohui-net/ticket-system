### 健康检查

#### 系统健康检查

```bash
# 基础健康检查
curl http://localhost:3000/health

# 数据库健康检查
curl http://localhost:3000/health/db

# Redis健康检查
curl http://localhost:3000/health/redis

# 完整健康检查
curl http://localhost:3000/health/all
```

**健康状态说明：**
- `200 OK` - 服务正常
- `503 Service Unavailable` - 服务异常

#### 定时健康检查脚本

创建 `/opt/scripts/health-check.sh`：

```bash
#!/bin/bash

# 健康检查脚本
LOG_FILE="/var/log/ticketing/health-check.log"
ALERT_EMAIL="admin@school.edu"

check_health() {
    local endpoint=$1
    local name=$2
    
    response=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000${endpoint})
    
    if [ "$response" != "200" ]; then
        echo "[$(date)] ALERT: $name health check failed (HTTP $response)" >> $LOG_FILE
        echo "Service $name is down (HTTP $response)" | mail -s "Alert: Ticketing System Health Check Failed" $ALERT_EMAIL
        return 1
    else
        echo "[$(date)] OK: $name health check passed" >> $LOG_FILE
        return 0
    fi
}

# 执行检查
check_health "/health" "System"
check_health "/health/db" "Database"
check_health "/health/redis" "Redis"
```

添加到crontab（每5分钟检查一次）：

```bash
*/5 * * * * /opt/scripts/health-check.sh
```

| 指标 | 警告阈值 | 严重阈值 | 处理建议 |
|------|---------|---------|---------|
| CPU使用率 | >70% | >90% | 检查进程，考虑扩容 |
| 内存使用率 | >80% | >95% | 重启服务或扩容 |
| 磁盘使用率 | >80% | >90% | 清理日志，扩容磁盘 |
| API响应时间 | >500ms | >2s | 检查数据库，优化查询 |
| 数据库连接数 | >80% | >95% | 检查连接泄漏 |
| 错误率 | >1% | >5% | 检查错误日志 |

## 备份恢复

### 数据库备份

#### 手动备份

```bash
# 创建备份目录
mkdir -p /backup/database

# 备份数据库
docker exec ticket-postgres-prod pg_dump -U ticketing ticketing > /backup/database/backup_$(date +%Y%m%d_%H%M%S).sql

# 压缩备份文件
gzip /backup/database/backup_$(date +%Y%m%d_%H%M%S).sql
```

#### 自动备份脚本

创建 `/opt/scripts/backup-database.sh`：

```bash
#!/bin/bash

# 配置
BACKUP_DIR="/backup/database"
RETENTION_DAYS=30
DB_CONTAINER="ticket-postgres-prod"
DB_USER="ticketing"
DB_NAME="ticketing"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份文件名
BACKUP_FILE="$BACKUP_DIR/backup_$(date +%Y%m%d_%H%M%S).sql"

# 执行备份
echo "[$(date)] Starting database backup..."
docker exec $DB_CONTAINER pg_dump -U $DB_USER $DB_NAME > $BACKUP_FILE

if [ $? -eq 0 ]; then
    # 压缩备份
    gzip $BACKUP_FILE
    echo "[$(date)] Backup completed: $BACKUP_FILE.gz"
    
    # 删除旧备份
    find $BACKUP_DIR -name "backup_*.sql.gz" -mtime +$RETENTION_DAYS -delete
    echo "[$(date)] Old backups cleaned (older than $RETENTION_DAYS days)"
else
    echo "[$(date)] Backup failed!"
    exit 1
fi
```

添加执行权限并设置定时任务：

```bash
chmod +x /opt/scripts/backup-database.sh

# 添加到crontab（每天凌晨2点备份）
crontab -e
0 2 * * * /opt/scripts/backup-database.sh >> /var/log/backup.log 2>&1
```

#### 数据库恢复

```bash
# 解压备份文件
gunzip /backup/database/backup_20240101_020000.sql.gz

# 恢复数据库
cat /backup/database/backup_20240101_020000.sql | \
docker exec -i ticket-postgres-prod psql -U ticketing ticketing

# 或使用单条命令
docker exec -i ticket-postgres-prod psql -U ticketing ticketing < /backup/database/backup_20240101_020000.sql
```

## 性能优化

### 数据库优化

#### 查询性能分析

```sql
-- 查看慢查询
SELECT query, calls, total_time, mean_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 10;

-- 查看表大小
SELECT 
    schemaname,
    tablename,
    pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;
```

#### 索引优化

```sql
-- 查看缺失的索引
SELECT 
    schemaname,
    tablename,
    attname,
    n_distinct,
    correlation
FROM pg_stats
WHERE schemaname = 'public'
ORDER BY n_distinct DESC;

-- 查看未使用的索引
SELECT 
    schemaname,
    tablename,
    indexname,
    idx_scan
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY pg_relation_size(indexrelid) DESC;
```

### SSL/TLS配置

#### 安装Let's Encrypt证书

```bash
# 安装Certbot
sudo apt install certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo certbot renew --dry-run
```

#### Nginx SSL配置

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    
    # HSTS
    add_header Strict-Transport-Security "max-age=31536000" always;
    
    # 其他安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
}
```

## 故障处理

### 常见故障

#### 1. 后端服务无响应

**症状：**
- API请求超时
- 健康检查失败

**排查步骤：**

```bash
# 1. 检查容器状态
docker ps | grep backend

# 2. 查看日志
docker-compose -f docker-compose.prod.yml logs --tail=100 backend

# 3. 检查进程
docker exec ticket-backend-prod ps aux

# 4. 检查资源使用
docker stats ticket-backend-prod

# 5. 重启服务
docker-compose -f docker-compose.prod.yml restart backend
```

#### 2. 数据库连接失败

**症状：**
- 后端日志显示数据库连接错误
- `/health/db` 返回错误

**排查步骤：**

```bash
# 1. 检查PostgreSQL容器
docker ps | grep postgres

# 2. 测试数据库连接
docker exec ticket-postgres-prod pg_isready -U ticketing

# 3. 查看连接数
docker exec ticket-postgres-prod psql -U ticketing -c \
"SELECT count(*) FROM pg_stat_activity;"

# 4. 检查磁盘空间
df -h

# 5. 重启数据库（谨慎）
docker-compose -f docker-compose.prod.yml restart postgres
```

#### 3. Redis连接失败

**症状：**
- `/health/redis` 返回错误
- 缓存功能异常

**排查步骤：**

```bash
# 1. 检查Redis容器
docker ps | grep redis

# 2. 测试Redis连接
docker exec ticket-redis-prod redis-cli ping

# 3. 查看Redis日志
docker-compose -f docker-compose.prod.yml logs redis

# 4. 检查内存使用
docker exec ticket-redis-prod redis-cli INFO memory

# 5. 重启Redis
docker-compose -f docker-compose.prod.yml restart redis
```

#### 4. 磁盘空间不足

**症状：**
- 服务无法写入日志
- 数据库操作失败

**处理步骤：**

```bash
# 1. 查看磁盘使用
df -h

# 2. 查找大文件
du -sh /* | sort -rh | head -10

# 3. 清理Docker
docker system prune -a -f

# 4. 清理日志
find /var/log -name "*.log" -mtime +30 -delete

# 5. 清理旧备份
find /backup -name "*.sql.gz" -mtime +30 -delete
```

#### 5. 内存不足

**症状：**
- 系统响应变慢
- OOM Killer杀死进程

**处理步骤：**

```bash
# 1. 查看内存使用
free -h

# 2. 查看进程内存
ps aux --sort=-%mem | head -10

# 3. 重启消耗内存最多的服务
docker-compose -f docker-compose.prod.yml restart backend

# 4. 清理缓存
echo 3 > /proc/sys/vm/drop_caches

# 5. 考虑扩容
```

### 紧急恢复流程

#### 服务完全不可用

```bash
# 1. 停止所有服务
docker-compose -f docker-compose.prod.yml down

# 2. 检查磁盘和内存
df -h && free -h

# 3. 重新启动
docker-compose -f docker-compose.prod.yml up -d

# 4. 监控启动日志
docker-compose -f docker-compose.prod.yml logs -f

# 5. 执行健康检查
curl http://localhost:3000/health/all
```

#### 数据损坏

```bash
# 1. 立即停止服务
docker-compose -f docker-compose.prod.yml stop

# 2. 从最近备份恢复
cat /backup/database/backup_latest.sql | \
docker exec -i ticket-postgres-prod psql -U ticketing ticketing

# 3. 验证数据完整性
docker exec ticket-postgres-prod psql -U ticketing -c "SELECT count(*) FROM tickets;"

# 4. 重启服务
docker-compose -f docker-compose.prod.yml start
```
